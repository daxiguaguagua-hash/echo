# 工作流 1: 跨模型审查

Claude (DeepSeek) 和 Codex (OpenAI) 各自独立审查同一个设计/代码，然后交叉对比。

**类型**: 稳定模式 — Issue 008、MCP 重构等多次验证。

## 触发条件

- 架构设计、数据模型设计
- 高风险代码变更
- 发布路径决策
- 用户明确要求"你们两个都看看"

## 流程

```
1. Claude 完成初步分析/设计，准备上下文包
2. 发给 Codex 独立审查
3. 交叉对比:
   - 一致点
   - Codex 独有发现
   - Claude 独有发现
4. 决定最终方案
```

## 目标状态（希望强制执行，历史上不是每次都做到）

- Codex 看到**完整上下文**，不只是摘要
- Codex 结论**原样展示**，不总结/过滤
- Claude 漏掉的问题**明确指出**，不粉饰

> **诚实标注**: 实际执行中，上下文打包、原样展示这些细节不是每次都做到。这是目标，不是已完成的状态。

## 实际案例

**Issue 008 设计**: Claude 分析了 Echo 工作区 18 个文件 → Codex 独立审查，发现了 Claude 漏掉的 template 污染问题、project 功能已部分实现的代码事实、import 覆盖风险。

**MCP Server 审查**: Claude 重构 → Codex 审查发现 3 P1 项 → 全部修复。

**工作流文档审查（本次）**: Claude 写 6 个工作流 → Codex 独立指出 30% 美化、漏掉的模式、冗余的工作流 → Claude 按反馈重构。
