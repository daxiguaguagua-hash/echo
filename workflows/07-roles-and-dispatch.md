# 角色分工与子 Agent 派发

Claude + Codex + Claude 子 agent 的三角分工。Codex 跨模型审查通过。

## 三角分工

```
用户 ──方向──→ Claude 主 agent（调度/集成 owner）
                │
                ├─ 设计阶段 ←→ Codex（独立审查 + 测试契约）
                │
                ├─ 实现阶段 → Claude 子 agent（封装好的闭环任务）
                │              或 Claude 自己做
                │
                ├─ 审计阶段 ← Codex（闭环完成审查）
                │
                └─ 集成/提交/状态更新（Claude 主 agent 独有职责）
```

| 角色 | 职责 | 不能做 |
|------|------|--------|
| **Claude 主 agent** | 调度者。维护上下文、拆闭环、派发任务、集成结果、跑门禁、更新状态 | — |
| **Claude 子 agent** | 执行封装好的闭环任务 | 自行改变契约、范围、核心设计 |
| **Codex** | 独立审计者 + 测试契约作者 | — |

## 子 Agent 派发决策

不是所有任务都派子 agent。按这个树判断：

```
准备做任务
  │
  ├─ 能写清输入/输出/验收命令？ → 否 → Claude 自己做
  │
  ├─ 会改共享核心/架构/数据模型？ → 是 → 先 Codex 设计审查
  │
  ├─ 文件边界独立？ → 否 → Claude 自己串行做
  │
  ├─ 任务大于约 15 分钟 或 明显可批量？ → 否 → Claude 自己做
  │
  └─ 是 → 派 子 agent
```

## 适合 vs 不适合

| 适合子 agent | 不适合 |
|-------------|--------|
| 独立调查：某模块现状、重复逻辑 | 需要连续决策的架构收敛 |
| 批量机械：测试、迁移、文档初稿 | 跨多模块实时调试 |
| 明确规格的单模块实现 | 模糊需求探索 |
| 代码审查/风险清单 | 需要和用户快速来回确认 |
| 生成对比矩阵、边界条件 | 依赖 Claude 刚发现的未记录上下文 |

## 派发任务包格式

每次派子 agent 必须带：

```
1. 目标：一句话
2. 涉及文件：精确路径列表
3. API 契约：输入/输出签名
4. Echo 不可变约束：哪些不能改
5. 验收命令：npm test / 具体命令
6. 完成后：只写代码，不 commit，不更新 STATUS
```

## 任务默认分配

| 任务类型 | 谁做 |
|---------|------|
| 架构/数据模型/发布决策 | Claude + Codex |
| 新模块契约测试 | Codex |
| 单模块明确实现 | Claude 子 agent 或 Claude 自己 |
| 跨模块集成/调试 | Claude 主 agent |
| 完成后风险审查 | Codex |
| 状态更新、验证门禁、提交 | Claude 主 agent |

## Codex 审查记录

- 方向基本现实，但 Claude 主 agent 必须是调度/集成 owner，不能只"等用户命令"
- "每个闭环都派子 agent"过度。小改、串行调试、强上下文任务应由 Claude 自己做
- 子 agent 不能替代 Codex 的外部审查角色
- 并行子 agent 必须保证文件边界不重叠
