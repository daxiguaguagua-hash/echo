# Echo 项目协作工作流

从 16 篇 Echo 文章 + 当前会话中提炼的实际合作模式。标记了哪些是**稳定模式**（已验证多次），哪些是**目标状态**（希望强制执行但历史上不是每次都做到）。

> **Codex 审查意见**: 70% 准确反映实际，30% 被美化。本版已根据审查修正。

## 横切门禁（所有工作流共用）

| 门禁 | 说明 |
|------|------|
| [不可变性优先](gates/invariant-first.md) | 文章正文不可改。所有设计和实现的第一道门。 |
| [验证门](gates/verification-gate.md) | 声称"完成"前必须跑测试 + 管线 + 更新 STATUS。 |

**任何工作流结束时，两条门禁都必须通过。**

## 工作流

| # | 工作流 | 类型 | 触发 |
|---|--------|------|------|
| 1 | [跨模型审查](01-cross-model-review.md) | 稳定模式 | 架构/高风险/不可逆决策 |
| 2 | [TDD + Codex 测试](02-tdd-with-codex.md) | 稳定模式（证据最强） | 新模块/新功能 |
| 3 | [数据审计](04-data-audit.md) | 稳定模式 | 数据状态不可信 |
| 4 | [Issue 驱动](06-issue-driven.md) | 稳定模式 | 多步骤实现 |
| — | [自主执行](03-autonomous-execution.md) | 元工作流 | 用户离开并授权 |
| — | [角色分工与派发](07-roles-and-dispatch.md) | 基础规则 | 谁做什么、何时派子 agent |
| — | [业界共识工作流](08-industry-workflow.md) | 核心流程 | Claude + Codex 独立搜索推演后的共识 |

## 选择指南（先问风险，再选流程）

```
任务进入
  │
  ├─ 触及文章正文？ → 先过【不可变性门禁】
  │
  ├─ 架构/高风险/不可逆？ → 跨模型审查 (1)
  │
  ├─ 数据状态不可信？ → 数据审计 (3)
  │
  ├─ 新模块/新功能？ → TDD + Codex 测试 (2)
  │
  ├─ 多步骤实现？ → Issue 驱动 (4)
  │
  ├─ 用户离开并授权？ → 自主执行（组合以上流程）
  │
  └─ 小改动/文案/单点修复？ → 直接改 + 测试 + STATUS
      （不强制 issue，但必须过验证门）
```

## 实际案例

| 工作流 | 案例 | 证据 |
|--------|------|------|
| 跨模型审查 | Issue 008 设计 | git log 显示 Claude + Codex 独立审查 |
| TDD + Codex | import 框架 | ECHO_STATUS 记录 Codex 106 测试 → 251 全绿 |
| 自主执行 | 用户"我先离开" | 7 commits，P0→P1 全部自主完成 |
| 数据审计 | 工作区 18 文件分类 | Codex 独立发现 template 污染 |
| Issue 驱动 | 每个 feature | issues/001-008 全部存在 |
